# 한이음 드림업 제출·실험 가이드

## 심사위원에게 전달할 한 문장

> ThermoShift는 특정 온도를 맞추는 온도조절기가 아니라, 재실 열부하와
> 미래 열환경을 예측해 재실자의 모델 쾌적도와 전기에너지를 동시에
> 최적화하는 장애 허용형 실시간 제어 시스템입니다.

발표 수식은 다음처럼 통일한다.

```text
min Σ [ λE·E(k) + λC·Poccupied(k)·ξ(k)^2 + λS·|Δu(k)| ]
ξ(k) = max(0, |PMV(k)| - 0.5)
```

온도는 RC 모델의 상태이고 설정온도는 액추에이터 명령이다. 목적함수에
설정온도 추종 오차는 없다. 전력 미교정 상태의 `E(k)`는 가동시간 대리지표,
입력전력 교정 후에는 Wh이며 두 결과를 섞어 부르지 않는다.

`λE`, `λC`, `λS`는 아직 통제 실험 전 설계값이다. 최종값은 여러 가중치에서
`Wh–PMV 대역 이탈률–switch count`를 그린 민감도/Pareto 분석으로 선정하고,
결과가 좋아 보이는 한 조합만 사후 선택하지 않는다.

“AI 에어컨”보다 **Physics–Estimation–Optimization 통합 폐루프**를 중심으로
설명한다. CO₂ 질량보존, HMM, RC 모델, MPC 각각을 새 발명이라고 주장하지
않고, 소규모 공간용 실제 장치와 안전·복구 구조까지 연결한 점을 차별점으로
제시한다.

## 결과 라벨

발표 슬라이드의 모든 숫자에는 다음 중 하나를 붙인다.

| 라벨 | 의미 | 필요한 근거 |
|---|---|---|
| `[MEASURED]` | 통제 프로토콜로 목업에서 측정 | 원본 로그, 반복 횟수, 센서·조건, 계산 코드 |
| `[SIM]` | 모델 내 시뮬레이션 | 모델식, 파라미터 출처, 기준정책, horizon |
| `[TARGET]` | 설계 목표 | 달성 결과처럼 표현하지 않음 |

현재까지 수집한 데이터는 개발·연결 점검용이다. 통제 조건과 ground truth가
부족하므로 세 라벨 중 `[MEASURED]` 성능 결과로 사용하지 않는다.
게이트웨이도 기본적으로 이 데이터에서 학습된 HMM 파일을 자동 사용하지
않는다. 새 라벨·hold-out 검증을 통과한 뒤 `use_learned_params`를 명시적으로
활성화한다.

20분 `pilot20` 시나리오는 히터·문·펠티어 이벤트와 센서 타임스탬프가
정렬되는지만 확인한다. 시정수 식별이나 PINN 학습용 최종 데이터로 사용하지
않는다. 종료 후 `python -m ml.export_experiment <run_id>`로 원본 CSV,
실제 이벤트, phase별 기울기와 제한사항이 포함된 manifest를 내보낸다.
DB 연결이 없는 라즈베리파이에서도 내보낸 폴더에
`python -m ml.prepare_experiment <run_dir>`를 실행하면 30초 통합표와 학습
품질 보고서를 재생성할 수 있다. PINN은 이 품질 게이트를 통과하지 못한
데이터를 기본적으로 거절하고, `--pipeline-smoke-test`일 때만 저장 없이
실행 경로를 시험한다.

## 주장 가능 범위

### 지금 코드와 장치로 주장 가능

- 20×20×30cm 목업에서 센서→추정→제어→로그의 폐루프를 구현했다.
- 센서 stale, 수동 잠금, 최소 가동·정지시간, 히터 watchdog을 구현했다.
- 네트워크 단절 시 Raspberry Pi 로컬 버퍼에 기록하고 복구 후 재전송한다.
- PIR·문·CO₂ 특징을 융합한 HMM 상태추정 구조를 구현했다.
- RC 열모델과 PMV 이탈·가동시간·제어변동을 함께 고려하는 후보정책 MPC 프로토타입을 구현했다.
- 10 W 히터 duty로 반복 가능한 합성 열부하 입력을 만들었다.

### 추가 통제 실험 후 주장 가능

- `[MEASURED]` 목업 RC 모델의 hold-out MAE/RMSE/R²
- `[MEASURED]` 동일 열부하에서 baseline 대비 소비전력(Wh) 변화
- `[MEASURED]` 온도 기반 쾌적 대리구간 이탈률 변화
- `[MEASURED]` actuator switching 횟수 변화
- 라벨이 있는 실제 공간 세션 확보 후 PIR 단독 대비 HMM의 F1/재현율 변화
- 실제 전력요금표와 부하계측 연결 후 TOU 비용 변화

### 말하면 안 되는 것

- “3시간 데이터로 100% 안정 동작”, “과적합 0%”
- “정적 재실 사각지대 100% 해결”, 근거 없는 감지율 100%
- 목업 PMV를 실제 사용자의 쾌적도 100%로 표현
- 모델이 계산한 가동시간 감소를 실제 전력 절감률로 표현
- switching 62.5% 감소를 마모 62.5% 감소 또는 수명 증가로 변환
- 목업 파라미터·절감률을 45m³ 공간에 1:1 확장
- 현재 1차원 Kalman 융합 코드를 EKF라고 표현
- 펠티어 목업을 설명하면서 압축기 보호 효과라고 표현

## 새 데이터 수집 프로토콜

### A. RC 파라미터 식별

준비:

- 펠티어 방열면을 상자 밖에 두고 교반팬을 동일 속도로 계속 가동한다.
- 외기/상자 주변 온도를 별도 센서로 함께 기록한다.
- 펠티어와 히터의 전압·전류 또는 입력전력을 측정한다.
- 센서 위치, 샘플링 주기, 문 상태를 고정한다.

한 run:

1. 히터 0%, 펠티어 OFF로 15분 안정화
2. 히터 duty를 정한 step/PRBS 계획으로 변화
3. 펠티어 OFF/ON 구간을 모두 포함
4. 종료 후 자연 회복 구간 기록
5. 식별용 run과 평가용 run을 날짜 또는 실행 단위로 완전히 분리

보고:

- 파라미터 `R/C/actuator efficiency` 또는 동등한 `a/b/d`
- calibration run 수와 hold-out run 수
- hold-out MAE, RMSE, R²와 잔차 시계열
- 외기 온도와 초기 조건

### B. baseline 대 MPC 비교

- baseline은 사전에 코드로 고정한 hysteresis thermostat로 정의한다.
- 동일한 히터 duty 프로파일과 유사한 초기온도(권장 ±0.2℃)를 사용한다.
- 순서 효과를 줄이도록 `AB/BA` 순서를 번갈아 최소 5쌍 반복한다.
- run 길이, 안정화 시간, 센서 위치, 교반팬을 동일하게 유지한다.
- 평균뿐 아니라 각 run 값, 표준편차와 신뢰구간을 함께 보고한다.

핵심 KPI:

```text
Energy_Wh = Σ voltage × current × Δt
Comfort-proxy violation = 허용 온도/모델 PMV 대역 밖 표본 / 전체 표본
Switch count = u(k) != u(k-1) 횟수
Data completeness = 수신 표본 / 기대 표본
```

목업에는 사람이 들어가지 않으므로 PMV는 `[SIM]` 모델 지표다. 실제 쾌적도
개선을 주장하려면 실제 공간에서 의복량, 활동량, 기류, 복사온도 가정을
명시하고 사용자 응답 또는 적절한 환경 실측을 추가한다.

## 추천 발표 구조

1. 문제: 고정 온도 제어가 공실·쾌적 상태에서도 불필요하게 동작
2. 핵심 정의: 쾌적도와 전력을 동시에 최적화
3. 통합 구조: 센서 융합 → 열부하 → RC 예측 → Economic MPC
4. 목업: 12 L, 펠티어, 10 W 합성 열부하, 실제 센서
5. 안전·신뢰성: watchdog, lockout, offline buffer, 판단 근거
6. 통제 실험: baseline과 MPC의 동일 외란 반복 비교
7. 결과: `[MEASURED]`와 `[SIM]`을 분리한 3개 KPI
8. 확장: 알고리즘 구조 재사용 + 공간별 현장 재교정

## 예상 심사 질문과 답변

1. **기존 MPC 연구와 무엇이 다른가?**
   개별 MPC 발명이 아니라 저비용 센서, 재실 추정, 합성 열부하, 물리모델,
   안전 제어, 장애 복구를 실제 엣지 장치에서 폐루프로 통합한 점입니다.

2. **데이터가 적은데 AI가 가능한가?**
   대규모 모델을 3시간 데이터로 학습한다고 주장하지 않습니다. RC 구조의
   소수 파라미터를 식별하고 hold-out run으로 오차를 검증합니다.

3. **현재 데이터가 성능 검증에 적합한가?**
   아닙니다. 기존 데이터는 개발 점검용으로 분리했고, 사전 정의한 통제
   프로토콜로 새 데이터를 수집합니다.

4. **왜 PIR만 사용하지 않았나?**
   PIR은 빠른 움직임에 강하지만 정적 재실에 약합니다. CO₂는 느리지만
   장시간 재실 정보를 보완해 서로 다른 시간 특성을 융합할 수 있습니다.

5. **CO₂로 인원수를 정확히 알 수 있나?**
   환기량과 혼합 지연의 영향을 받으므로 정확하다고 단정하지 않습니다.
   실제 공간에서 체적·ACH를 교정하고 라벨 데이터로 성능을 평가해야 합니다.

6. **EKF인가?**
   현재 인원수 프로토타입은 질량보존 역산값에 대한 1차원 Kalman 융합입니다.
   비선형 상태벡터 EKF로 과장하지 않습니다.

7. **100 W/인은 정확한가?**
   휴식 성인의 대표값을 사용한 근사입니다. 실제 적용에서는 활동량에 따라
   `q_person`을 교정하거나 범위로 다룹니다.

8. **PMV -0.5~0.5를 보장하는가?**
   현재는 목적함수 soft penalty이며 hard constraint가 아닙니다. 또한 목업
   PMV는 사람 만족도 실측이 아니라 환경값 기반 모델 지표입니다.

9. **32.9% 절감이 실측인가?**
   현재 그 수치는 사용하지 않습니다. 전력계와 반복 통제 실험으로 얻은
   `[MEASURED]` Wh만 실측 절감으로 발표합니다.

10. **switching 감소가 수명 증가를 뜻하나?**
    아닙니다. 측정한 switching 횟수 감소만 보고하고 수명으로 환산하지 않습니다.

11. **12 L 결과가 실제 방에 적용되는가?**
    파라미터나 성과는 이전하지 않습니다. 모델·제어 아키텍처를 재사용하고
    실제 방의 R, C, ACH, 액추에이터 효율을 다시 식별합니다.

12. **목업 히터가 사람을 재현하는가?**
    사람의 열부하 한 측면만 반복 가능한 입력으로 재현합니다. CO₂와 PIR은
    재현하지 않으므로 인원 감지 성능 검증과 분리합니다.

13. **네트워크가 끊기면 어떻게 되는가?**
    안전 판단은 엣지에서 계속하고, DB 쓰기는 SQLite에 순서대로 보관했다가
    연결 복구 후 재전송합니다.

14. **생성형 AI가 잘못 말하면 제어도 잘못되는가?**
    생성형 AI는 저장된 판단을 자연어로 설명할 뿐 제어 결정·안전 경로에는
    참여하지 않습니다.

15. **수상작으로서 한 장면만 보여준다면?**
    동일 열부하에서 baseline과 MPC가 서로 다른 명령을 내리고, 실제 전력·
    허용대역 이탈·스위칭 KPI가 실시간으로 갱신되는 폐루프 장면입니다.

16. **결국 24℃를 잘 맞추는 시스템 아닌가?**
    아닙니다. 목적함수에는 설정온도 오차가 없습니다. 온도·습도와 명시한
    met/clo/기류/복사온도 가정으로 미래 PMV를 계산하고, 재실 시 PMV 대역
    이탈과 전기에너지를 함께 줄이는 제어입력을 선택합니다.
